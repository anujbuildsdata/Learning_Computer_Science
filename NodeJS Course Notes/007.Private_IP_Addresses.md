# Private IP Addresses — What They Are and Why They Exist

> **One-line meaning:** a private IP address is an address that **only works inside your own network**. It cannot travel across the internet. Your router swaps it for its own public address when you go outside.

---

## 1. First, what is an IP address?

An **IPv4 address** is a 32-bit number written as four numbers (called **octets**) separated by dots:

```text
  192  .  168  .   1   .  10
   ↑        ↑       ↑      ↑
 8 bits  8 bits  8 bits  8 bits  = 32 bits total
```

Each octet ranges from **0 to 255**, so the whole space is about **4.3 billion** addresses (2³²).

An address has two jobs at once:

| Part | Job | Example (`192.168.1.10`) |
|------|-----|--------------------------|
| **Network part** | Which network am I on? | `192.168.1` |
| **Host part** | Which device am I on that network? | `.10` |

---

## 2. Public vs private — the core idea

**Real-life analogy:** a **public IP** is a street address that the postal service can deliver to from anywhere in the world. A **private IP** is an **apartment number inside a building** — meaningful only to people already inside that building.

```text
Internet                Your home network
────────                ─────────────────
                        ┌─────────────────────────┐
  203.0.113.7  ◄──────► │ Router                  │
  (public IP)           │ 192.168.1.1 (private)   │
                        └───────┬─────────────────┘
                                │
              ┌─────────────────┼──────────────────┐
         192.168.1.10      192.168.1.11       192.168.1.12
           laptop             phone               TV
```

- Every device at home has a **private** address.
- The router has a **public** address facing the internet.
- Two different homes can both use `192.168.1.10` without conflict, because those addresses never leave their own networks.

---

## 3. Why private addresses exist

IPv4 has only about **4.3 billion** addresses. There are far more devices than that. Two things saved the internet:

1. **Private ranges (RFC 1918)** — reuse the same addresses inside every network.
2. **NAT (Network Address Translation)** — let a whole network share one public IP.

Without them, the internet would have run out of addresses around 2011 (which is exactly when the last IPv4 blocks were handed out).

---

## 4. How NAT works (step by step)

You open `https://example.com` from `192.168.1.10`.

```text
1. Laptop sends a packet:
      from 192.168.1.10:51820  →  to 93.184.216.34:443

2. Router rewrites the source to its public IP and remembers the mapping:
      203.0.113.7:41000  ↔  192.168.1.10:51820

3. The website replies to 203.0.113.7:41000.

4. Router looks up its table, rewrites the destination back to
   192.168.1.10:51820, and forwards it to your laptop.
```

The mapping lives in a **NAT table** in the router's memory. This is also why, from the outside, an unsolicited connection cannot reach your laptop — there is no entry in the table for it.

## 5. The three private ranges (RFC 1918)

| Range | CIDR | Number of addresses | Old class | Typical use |
|-------|------|---------------------|-----------|-------------|
| `10.0.0.0` – `10.255.255.255` | `10.0.0.0/8` | 16,777,216 | Class A | Large organisations, data centres, cloud VPCs, VPNs |
| `172.16.0.0` – `172.31.255.255` | `172.16.0.0/12` | 1,048,576 | Class B | Medium networks, Docker's default bridge (`172.17.0.0/16`) |
| `192.168.0.0` – `192.168.255.255` | `192.168.0.0/16` | 65,536 | Class C | Home routers and small offices |

All three are **free to use by anyone**, on any network, with no registration — that is exactly why they are the standard choice for local networks.

### Why those sizes?

Each range is a block of 2ⁿ addresses:

```text
10.0.0.0/8    → the first octet is fixed      → 2^24 = 16,777,216 addresses
172.16.0.0/12 → the first 12 bits are fixed   → 2^20 =  1,048,576 addresses
192.168.0.0/16→ the first 16 bits are fixed   → 2^16 =     65,536 addresses
```

Big organisations get the huge `/8` block; a home router only needs a `/24` slice of `192.168.x.x`.

---

## 6. A note on "Class A / B / C"

The class system is **history**. It divided the address space by the first bits of the address:

| Class | First octet | Default mask | Meaning |
|-------|-------------|--------------|---------|
| A | 1 – 126 | `/8` | Very large networks |
| B | 128 – 191 | `/16` | Medium networks |
| C | 192 – 223 | `/24` | Small networks |
| D | 224 – 239 | — | Multicast |
| E | 240 – 255 | — | Experimental / reserved |

Since **CIDR** (1993), the slash number describes the size instead, so a "Class C range" now just means "a `/24`-ish block". You still hear the terms because old documentation and old exam questions use them.

## 7. Things people get wrong

**"Private IP means secure."**
No. It means *not routable on the internet*. Inside your LAN, anyone on the same Wi-Fi can reach a private address unless a firewall stops them.

**"Private addresses are assigned by IANA to me."**
No. Nobody owns them and nobody tracks them. Every network may use them, which is why overlapping ranges are a real problem when two companies merge or when a VPN connects two networks that both use `192.168.1.x`.

**"169.254.x.x is private."**
Almost. `169.254.0.0/16` is **link-local** (APIPA), not RFC 1918. A device gives itself one of these when DHCP fails — seeing `169.254.x.x` usually means "no working DHCP server", not "private network".

**"The router's public IP is mine."**
It changes often (dynamic IP), and with CGNAT you may not even have a public IPv4 of your own — you may be sharing one with many other customers.

## 8. Finding your own addresses

```bash
# Linux
ip addr show              # modern
ip -4 addr                # IPv4 only
hostname -I               # just the addresses

# macOS / older Linux
ifconfig

# Windows
ipconfig                  # add /all for MAC, DNS and DHCP details

# Public IP (as the internet sees you)
curl ifconfig.me
```

A home machine typically shows:

```text
inet 192.168.1.10/24    ← private address on your LAN
```

## 9. Summary

| Question | Answer |
|----------|--------|
| What is a private IP? | An address usable only inside a local network |
| Can it be routed on the internet? | No — routers drop it |
| Who assigns them? | You (or your router's DHCP) — no registration needed |
| Who defines them? | RFC 1918: `10/8`, `172.16/12`, `192.168/16` |
| Why do they exist? | To reuse addresses and survive IPv4 exhaustion |
| How does a private host reach the internet? | Through NAT on the router |
| Can two networks use the same private range? | Yes — until you connect them together |
