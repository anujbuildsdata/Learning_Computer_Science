# Reserved IP Address Ranges (First-to-Last Format)

> The same reserved blocks as [008](008.Reserved_IP_Addresses.md), written as **`first address - last address`** instead of `address/prefix`. This note explains how to convert between the two forms and how to calculate the number of addresses yourself.

---

## 1. Two ways to write the same block

A block of addresses can be described in two equivalent ways:

| Form | Example | Reads as |
|------|---------|----------|
| **CIDR** (prefix) | `192.168.0.0/16` | "Start here, keep the first 16 bits fixed" |
| **Min–max** (range) | `192.168.0.0 - 192.168.255.255` | "From this address to that address" |

Both describe **exactly the same set**. CIDR is compact and is what routers and firewalls use; min–max is easier for humans and for tools that only accept "from … to …" fields.

**Real-life analogy:** a floor in a building can be described as "floor 3" (compact, needs the building's rules to interpret) or as "rooms 300 to 399" (explicit, needs no rules).

---

## 2. Converting CIDR → first and last address

```text
1. block size  = 2^(32 - prefix)
2. first       = start address (must be a multiple of block size)
3. last        = first + block size - 1
```

### Worked example: `172.16.0.0/12`

```text
block size = 2^(32-12) = 2^20 = 1,048,576 addresses

The first 12 bits are fixed: 8 bits of "172" + 4 bits of the second octet.
Those remaining 4 free bits of octet 2 can count 0..15.

So octet 2 runs   16 .. 16+15 = 31
Range: 172.16.0.0 - 172.31.255.255   ✅  (1,048,576 addresses)
```

### Worked example: `100.64.0.0/10`

```text
block size = 2^22 = 4,194,304

10 fixed bits = 8 bits of "100" + 2 bits of octet 2.
64 in binary is 0100 0000, so those top 2 fixed bits are "01".
The other 6 bits of octet 2 are free → 01000000..01111111 = 64..127.

Range: 100.64.0.0 - 100.127.255.255   ✅  (64 × 65,536 = 4,194,304)
```

### Worked example: `198.18.0.0/15`

```text
block size = 2^17 = 131,072 = two /16 blocks

Range: 198.18.0.0 - 198.19.255.255   ✅
```

> **Rule of thumb:** the range always starts on a **multiple of its own size**. `192.168.0.0/16` is fine; `192.168.5.0/16` is not a valid block start — the tool will round it down to `192.168.0.0`.

## 3. Converting first/last address → CIDR

Two addresses become **one** CIDR block only if they cover a power-of-two block starting on the right boundary. Otherwise the answer is **several** CIDR blocks.

```text
172.16.0.0 - 172.31.255.255
→ spans exactly 16 × /16
→ 172.16.0.0/12         ✅ one block

10.0.0.5 - 10.0.0.9
→ only 5 addresses, not a power of two aligned at the start
→ 10.0.0.5/32, 10.0.0.6/31, 10.0.0.8/31   (three blocks)
```

Doing this by hand is error-prone — use a calculator:

```python
import ipaddress

# range → list of CIDR blocks
print([str(n) for n in ipaddress.summarize_address_range(
    ipaddress.IPv4Address("172.16.0.0"),
    ipaddress.IPv4Address("172.31.255.255"))])      # ['172.16.0.0/12']

# CIDR → first, last, count
net = ipaddress.ip_network("100.64.0.0/10")
print(net.network_address, net.broadcast_address, net.num_addresses)
```

```bash
# command-line alternative
ipcalc 192.168.0.0/16
```

## 6. Reading a row correctly — three common traps

**Trap 1 — `172.16/12` is not `172.0/12`.**
The block starts at `172.16`, not `172.0`. `172.0.0.1` is a perfectly ordinary public address; it is **not** private.

**Trap 2 — `192.168/16` is not `/24`.**
`192.168.0.0/24` covers only `192.168.0.x` (256 addresses). `192.168.0.0/16` covers everything from `192.168.0.0` to `192.168.255.255` (65,536 addresses). Home routers hand out `/24`s *out of* the `/16`.

**Trap 3 — the broadcast address sits inside `240/4`.**
`255.255.255.255` falls inside `240.0.0.0/4`, yet it is listed separately because it has its own special meaning ("everyone on this LAN") rather than "reserved for the future".

**Also:** `100.64/10` is **not** private in the RFC 1918 sense — it is shared address space for carrier NAT. Most home devices never see it, but you will meet it on mobile or fixed-wireless connections.

## 7. Which format do you use where?

| Situation | Format usually given |
|-----------|----------------------|
| Router / firewall / `ufw` / `iptables` rules | CIDR (`10.0.0.0/8`) |
| Cloud security groups (AWS, Azure, GCP) | CIDR |
| `ip route` / routing tables | CIDR |
| Spreadsheets, vendor "blocked IP" lists | Min–max range |
| Old firewall GUIs with "From / To" boxes | Min–max range |
| `ipaddress` / `netaddr` libraries | Either — they convert both |

If a tool asks for a range and you only have a prefix, compute the last address with the formula in section 2. If a tool asks for a prefix and you have a range, check whether it is exactly one aligned power-of-two block; if not, split it.

---

## 8. Summary

- **CIDR** = start address + number of fixed bits. **Min–max** = first and last address. Same thing, different clothing.
- `block size = 2^(32 - prefix)`; the last address is `first + block size - 1`.
- The start address must be a multiple of the block size.
- Memorise the private trio in range form: `10.0.0.0-10.255.255.255`, `172.16.0.0-172.31.255.255`, `192.168.0.0-192.168.255.255`.
- Watch the boundaries: `172.16` (not `172.0`), `192.168/16` (not `/24`), and `100.64/10` (carrier NAT, not RFC 1918).
