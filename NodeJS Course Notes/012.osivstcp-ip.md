# OSI vs TCP/IP Model — The Layers of a Network

> **Simple meaning:** both models describe the **same journey** a piece of data takes from one computer to another. They just cut that journey into a different number of steps.
>
> - **OSI** = 7 layers, the teaching/reference model.
> - **TCP/IP** = 4 layers, the model the real internet actually runs on.

---

## 1. Why split networking into layers?

**Real-life analogy:** sending a parcel.

You do not personally drive the truck, print the address label, pack the box, and build the road. Different departments handle each job, and each one only needs to know its own part:
- You decide **what** to send (content).
- Packing decides **how** it is boxed and protected.
- The courier decides the **route**.
- The driver handles the **physical roads**.

Layers give the same benefit:

| Benefit | Meaning |
|---------|---------|
| **Divide and conquer** | Each layer solves one problem only |
| **Interchangeable parts** | Swap Wi-Fi for Ethernet without changing HTTP |
| **Easier debugging** | "Is this a cable problem, an IP problem, or an app problem?" |
| **Standardisation** | Anyone can build a layer as long as it follows the contract |

## 2. The OSI model, layer by layer

| # | Layer | In one sentence | Examples |
|---|-------|-----------------|----------|
| **7** | **Application** | The service the user's program asks for | HTTP, HTTPS, DNS, SMTP, FTP, SSH |
| **6** | **Presentation** | Translates, encrypts, compresses data into a usable format | TLS, JPEG, PNG, UTF-8, gzip |
| **5** | **Session** | Opens, keeps alive and closes a conversation | Session tokens, RPC, NetBIOS, sockets |
| **4** | **Transport** | End-to-end delivery between programs, with ports | TCP, UDP, QUIC |
| **3** | **Network** | Addressing and routing between different networks | IP, ICMP, routing protocols (OSPF, BGP), routers |
| **2** | **Data Link** | Delivery between two devices on the **same** link | Ethernet, Wi-Fi (802.11), MAC addresses, switches |
| **1** | **Physical** | Actual bits as electricity, light or radio | Cables, fibre, radio waves, pins, voltages |

### A memory trick

**Top → bottom:** **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing
**Bottom → top:** **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way

### Layer 7 vs the rest — a common confusion

"Layer 7" does **not** mean the app you installed. It means the **protocol** the app speaks (HTTP, DNS). A load balancer that "works at layer 7" understands HTTP URLs; one that works at layer 4 only understands IPs and ports.

---

## 3. The TCP/IP model, layer by layer

The real internet uses four layers:

| # | Layer | Purpose | Protocols |
|---|-------|---------|-----------|
| **4** | **Application** | Everything the programs care about | HTTP, DNS, SMTP, SSH, TLS |
| **3** | **Transport** | End-to-end delivery, ports, reliability choice | TCP, UDP |
| **2** | **Internet** | Addressing and routing across networks | IP (v4/v6), ICMP |
| **1** | **Network Access** (Link) | Moving frames on the local link, and the wire itself | Ethernet, Wi-Fi, ARP |

The TCP/IP model merges OSI's **application + presentation + session** into one **Application** layer, and merges **data link + physical** into **Network Access**.

---

## 4. The comparison table

| **OSI Model Layer** | **TCP/IP Model Layer** | **Data Name (PDU)** | **Description** |
|---------------------|------------------------|---------------------|-----------------|
| **Application (7)** | **Application** | **Data** | Services for end-user applications: HTTP, FTP, DNS, SMTP. |
| **Presentation (6)** | **Application** | **Data** | Data format translation, encryption, compression. |
| **Session (5)** | **Application** | **Data** | Establishes, maintains and ends sessions. |
| **Transport (4)** | **Transport** | **Segment (TCP)** / **Datagram (UDP)** | Reliable or fast delivery; adds port numbers. |
| **Network (3)** | **Internet** | **Packet** | Logical addressing (IP) and routing between networks. |
| **Data Link (2)** | **Network Access** | **Frame** | Frames, MAC addresses, error checking on one link. |
| **Physical (1)** | **Network Access** | **Bits** | Raw binary as electrical, optical or radio signals. |

**PDU** = *Protocol Data Unit* — the name of the data chunk **at that layer**. The bytes are the same data; only the name and the wrapper change.

## 5. Encapsulation — what actually happens when you type a URL

**Real-life analogy:** putting a letter into an envelope, then into a parcel box, then onto a truck. Each stage adds a wrapper and never needs to open the previous one.

```text
You type:  https://example.com/login

Layer 7/Application :  HTTP request
   GET /login HTTP/1.1
   Host: example.com
        │
        ▼
Layer 6/Presentation:  TLS encrypts it (for HTTPS)
        │
        ▼
Layer 4/Transport   :  TCP adds source port + destination port 443
   ┌──────────────┬─────────────────────────┐
   │ TCP header   │ encrypted HTTP request  │   ← Segment
   └──────────────┴─────────────────────────┘
        │
        ▼
Layer 3/Network     :  IP adds source + destination IP address
   ┌──────────┬────────────┬─────────────────┐
   │ IP header│ TCP header │  payload        │   ← Packet
   └──────────┴────────────┴─────────────────┘
        │
        ▼
Layer 2/Data Link   :  Ethernet adds MAC addresses + checksum
   ┌──────────┬──────────┬────────────┬─────────┐
   │ Ethernet │ IP header│ TCP header │ payload │   ← Frame
   └──────────┴──────────┴────────────┴─────────┘
        │
        ▼
Layer 1/Physical    :  the frame becomes electrical / optical / radio signals
   0101101011100010111...
```

The receiver does the opposite — **decapsulation** — stripping one wrapper at a time until the program gets the original request.

> This is why every layer's header is "inside" the next one. The envelope never needs to know what is written on the letter.

## 6. Which device / protocol lives where

| Layer | Devices | Protocols / concepts |
|-------|---------|----------------------|
| 7 Application | Load balancers (L7), proxies, WAFs | HTTP, DNS, SMTP, SSH |
| 4 Transport | Load balancers (L4), NAT gateways | TCP, UDP, ports |
| 3 Network | **Routers** | IP, ICMP, subnets, routing tables |
| 2 Data Link | **Switches**, bridges, wireless APs | Ethernet, MAC addresses, VLANs |
| 1 Physical | **Hubs**, cables, connectors, antennas | Bits, voltage, frequency |

**Handy rule:** a **switch** forwards by **MAC** (layer 2), a **router** forwards by **IP** (layer 3), a **hub** just repeats electricity (layer 1).

## 7. Using the layers to troubleshoot

Work up from the bottom — the cheapest checks first:

```text
1. Physical   Is the cable plugged in? Is Wi-Fi associated?  → any link light?
2. Data Link  Do I get an IP by DHCP? Do other devices on this Wi-Fi work?
3. Network    ping 8.8.8.8                     → is routing/DNS-independent reachability OK?
4. Transport  nc -zv host 443, ss -tulpn       → is the port open and listening?
5. Application curl -v https://example.com     → does the service answer correctly?
```

Typical diagnosis:

| Test result | Conclusion |
|-------------|------------|
| `ping 8.8.8.8` fails | Problem at layer 1–3 (cable, Wi-Fi, IP, routing) |
| `ping 8.8.8.8` works, `ping google.com` fails | **DNS** problem (layer 7-ish) |
| Ping works, `curl` to port 443 fails | Firewall or nothing listening (layer 4) |
| `curl` gets a 500 error | The network is fine — the **application** is broken |

This step-by-step narrowing is the single most practical thing the OSI model gives you.

---

## 8. Why both models exist

| Question | Answer |
|----------|--------|
| Is OSI a real protocol suite? | It exists (OSI/ISO protocols) but almost nobody uses it. The **model** survived; the protocols did not. |
| Why do we still learn it? | It has finer separation (presentation, session), which is great vocabulary for describing *where* something happens. |
| Why does the internet use TCP/IP? | It was simpler, shipped earlier, and was free to implement. |
| Do they conflict? | No. TCP/IP layers map neatly onto OSI layers; people say "layer 7 load balancer" using OSI numbers even on a TCP/IP network. |

---

## 9. Summary

- **Layer = one job.** Each layer wraps the data from the layer above it.
- **OSI has 7 layers**; **TCP/IP has 4**. Application/Presentation/Session collapse into Application; Data Link/Physical collapse into Network Access.
- **PDU names:** Data → Segment/Datagram → Packet → Frame → Bits.
- **Encapsulation** adds headers on the way out; **decapsulation** removes them on the way in.
- **Switch = MAC (L2)**, **router = IP (L3)**, **hub = bits (L1)**.
- Troubleshoot by climbing the layers: cable → IP → port → application.
