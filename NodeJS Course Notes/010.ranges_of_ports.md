# Port Ranges — What a Port Is and Why It Is Numbered

> **Simple meaning:** an IP address gets you to the **machine**. A port gets you to the **program on that machine**.
>
> One server can run a web server, a database and SSH at the same time on one IP address — the port number is what tells the network which program a packet is for.

---

## 1. The address-and-desk analogy

A company building has one street address, but many desks inside.

| Real life | Networking |
|-----------|------------|
| Street address of the building | **IP address** (`203.0.113.7`) |
| Desk number inside | **Port number** (`:443`) |
| "Deliver to desk 443" | A packet with destination port 443 |
| Which desk sent the letter | **Source port** (the client's own port) |

A port is just a **16-bit number**, so it can be anything from **0 to 65,535**. That gives 65,536 possible "desks" per IP address.

> **Important:** a port is not a physical thing. It is a number in the packet header that the operating system uses to choose which program should receive the data.

---

## 2. Why ports are needed

Without ports, a computer could run only one network service at a time — the browser could not talk to a website while SSH was open.

With ports:

```text
203.0.113.7:22    → sshd      (remote login)
203.0.113.7:80    → nginx     (web)
203.0.113.7:443   → nginx     (secure web)
203.0.113.7:5432  → postgres  (database)
```

All four live on one IP address and never get each other's traffic.

## 3. The three ranges

| **Range** | **Category** | **Description** |
|-----------|--------------|-----------------|
| **0–1023** | **Well-Known Ports** (system ports) | Reserved for standard services. Binding to one requires administrator/root privileges. |
| **1024–49151** | **Registered Ports** (user ports) | Registered with IANA for particular applications. Usable by any user. |
| **49152–65535** | **Dynamic / Private Ports** (ephemeral) | Temporary ports picked by the operating system for outgoing connections. |

### 3.1 Well-known ports: 0 – 1023

These are the "official" doors of the internet: 22 for SSH, 53 for DNS, 80 for HTTP, 443 for HTTPS.

- Only **root** (or a process with `CAP_NET_BIND_SERVICE` on Linux) may listen on them.
- **Why the restriction?** Trust. If any user could open port 22, they could impersonate SSH on a shared machine. The restriction means "if something is listening on 22, an administrator allowed it".
- Port **0** is reserved and cannot be used for a normal service.

### 3.2 Registered ports: 1024 – 49151

Ports with a documented purpose, but no privilege needed: 3306 MySQL, 5432 PostgreSQL, 3389 RDP, 8080 alternative HTTP.

- "Registered" does **not** mean reserved. Nothing stops another program from using 3306 — which is exactly why two database servers on one machine need a config change.
- IANA keeps the list; registration is a request, not enforcement.

### 3.3 Dynamic / private ports: 49152 – 65535

Used for **outgoing** connections. When your browser opens a connection, the OS picks a free high number as the **source port**:

```text
192.168.1.10:51820  →  203.0.113.7:443
└──── yours ────┘      └── server ──┘
  ephemeral port       well-known port
```

When the connection closes, the port is released and can be reused.

**Real-world wrinkle:** the ranges above are the IANA definition, but operating systems differ:

| System | Ephemeral range actually used |
|--------|-------------------------------|
| Linux | `32768–60999` by default (see `/proc/sys/net/ipv4/ip_local_port_range`) |
| Windows | `49152–65535` |
| macOS | `49152–65535` |

So on Linux, ordinary programs may also use ports from the 32768–49151 part of the "registered" range. The labels describe intent, not a hard rule.

## 4. A connection is identified by four numbers

A single port is not enough. A connection (a **socket**) is identified by the **4-tuple**:

```text
(source IP, source port, destination IP, destination port)
```

That is why your browser can open **two tabs to the same site at once**: both go to `203.0.113.7:443`, but each uses a different local source port.

```text
192.168.1.10:51820 → 203.0.113.7:443   (tab 1)
192.168.1.10:51821 → 203.0.113.7:443   (tab 2)
```

## 5. Seeing ports on your own machine

```bash
# Linux: all listening TCP/UDP ports with the owning process
ss -tulpn

# Older equivalent
netstat -tulpn

# Who is using one specific port?
lsof -i :3000
ss -ltnp 'sport = :3000'

# Windows
netstat -ano | findstr LISTENING

# Check the Linux ephemeral range
cat /proc/sys/net/ipv4/ip_local_port_range
```

Sample `ss` output:

```text
Netid State  Local Address:Port   Peer Address:Port  Process
tcp   LISTEN 0.0.0.0:22           0.0.0.0:*          users:(("sshd",pid=712))
tcp   LISTEN 127.0.0.1:5432       0.0.0.0:*          users:(("postgres",pid=901))
tcp   ESTAB  192.168.1.10:51820   93.184.216.34:443  users:(("firefox",pid=2210))
```

| Column | Meaning |
|--------|---------|
| `LISTEN` | Waiting for incoming connections |
| `ESTAB` | A live, established connection |
| `0.0.0.0:22` | Listening on **every** interface (reachable from outside) |
| `127.0.0.1:5432` | Listening **only** on loopback (local machine only) |
| `Peer Address` | The other end of the connection |

That `0.0.0.0` vs `127.0.0.1` difference is a frequent security surprise: a database on `0.0.0.0:5432` is exposed to the network; on `127.0.0.1:5432` it is not.

## 6. Common problems involving ports

| Symptom | Likely cause |
|---------|--------------|
| `Address already in use` | Another process is on that port → `ss -tulpn \| grep :3000` |
| `Permission denied` when binding port 80 | Non-root user on a well-known port → use 8080 or grant `CAP_NET_BIND_SERVICE` |
| `Connection refused` | Nothing is listening on that port, or a firewall sends a reset |
| `Connection timed out` | A firewall is silently dropping packets |
| "Cannot connect to my server from another machine" | Server bound to `127.0.0.1` instead of `0.0.0.0` |
| `TIME_WAIT` piling up / "cannot assign requested address" | Ephemeral ports exhausted by too many short connections |

---

## 7. Summary

| Range | Name | Who uses it | Needs root? |
|-------|------|-------------|-------------|
| 0–1023 | Well-known | Standard services (HTTP, SSH, DNS) | Yes |
| 1024–49151 | Registered | Applications (MySQL, RDP, dev servers) | No |
| 49152–65535 | Dynamic / ephemeral | Client-side outgoing connections | No |

- A port is a **16-bit number (0–65535)** that selects a program on a machine.
- IP address = which computer; port = which program.
- The first 1024 need privileges because they carry trust.
- Your OS quietly picks a high **source port** for every outgoing connection.
- A connection is the **4-tuple** of source IP, source port, destination IP, destination port.
