# SSH Commands — Check, Install, Start and Connect

> **SSH (Secure Shell)** lets you log in to another computer over the network and run commands on it — with everything **encrypted**.
>
> **Real-life analogy:** an armoured car with a locked cabin. The road is public, but nobody can see or change what is being carried. Old tools like Telnet are the same car with the windows open.

---

## 1. How SSH actually works

```text
[ Your machine ]  ── encrypted TCP connection, port 22 ──►  [ Server ]
   ssh client                                                sshd (server)
```

Two parts are needed:

| Part | Package | Runs on | Job |
|------|---------|---------|-----|
| **Client** | `openssh-client` | Your machine | Starts the connection (`ssh user@host`) |
| **Server** | `openssh-server` | The machine you log into | Listens on port 22 and accepts logins |

You normally already have the client. You only install the **server** on the machine you want to reach.

The connection has three stages:

1. **Key exchange** — both sides agree on encryption keys (Diffie–Hellman). Everything after this is encrypted.
2. **Host verification** — the server proves its identity with its host key; you are asked to confirm the fingerprint the first time.
3. **Authentication** — you prove who *you* are, with a password or (better) an SSH key.

## 2. Check if SSH is installed

```bash
# Client version (capital V — lowercase -v means "verbose", a very different thing)
ssh -V
# OpenSSH_9.6p1 Ubuntu-3ubuntu13, OpenSSL 3.0.13

# Is the client package installed? (Debian / Ubuntu)
dpkg -l | grep openssh-client

# Is the server package installed?
dpkg -l | grep openssh-server
```

How to read that:

| Part | Meaning |
|------|---------|
| `dpkg -l` | List installed packages |
| `grep openssh-client` | Keep only matching lines |
| `ii` in the output | `i` = desired: install, `ii` = installed and configured |
| no output | The package is **not** installed |

**Fedora / RHEL / Rocky:**

```bash
rpm -qa | grep openssh
```

**Quick functional test (works everywhere):**

```bash
ss -tlnp | grep :22      # is anything listening on port 22?
```

## 3. Install SSH

```bash
# 1. Refresh the list of available packages
sudo apt update

# 2. Install the server
sudo apt install openssh-server
```

What each word does:

| Word | Meaning |
|------|---------|
| `sudo` | Run as administrator (root) — installing software needs it |
| `apt` | The Debian/Ubuntu package manager |
| `update` | Download the **list** of available packages (does not upgrade anything) |
| `upgrade` | Actually install newer versions of installed packages |
| `install openssh-server` | Download and install this package |

> `apt update` is the step people skip, and then they get "package not found" for a package that clearly exists.

On Fedora/RHEL the equivalent is:

```bash
sudo dnf install openssh-server
```

Verify the install:

```bash
ssh -V
systemctl status ssh
```

## 4. Check the SSH server status

```bash
sudo systemctl status ssh
```

Sample output, and what matters in it:

```text
● ssh.service - OpenBSD Secure Shell server
     Loaded: loaded (/lib/systemd/system/ssh.service; enabled; preset: enabled)
     Active: active (running) since Mon 2026-10-19 09:14:02 UTC; 2h 11min ago
   Main PID: 712 (sshd)
```

| Line | Meaning |
|------|---------|
| `Loaded: ... enabled` | Will start automatically at boot |
| `Active: active (running)` | Currently working |
| `Active: inactive (dead)` | Installed but not running |
| `Main PID` | The process ID of the listening server |

> On Fedora/RHEL the service is called **`sshd`**, not `ssh`. If `systemctl status ssh` says "Unit not found", try `systemctl status sshd`.

## 5. Start the SSH server

```bash
# Start it right now (this boot only)
sudo systemctl start ssh

# Also start it automatically on every boot
sudo systemctl enable ssh
```

**`start` vs `enable` — the difference people always mix up:**

| Command | Effect | Survives reboot? |
|---------|--------|------------------|
| `systemctl start ssh` | Runs the service now | ❌ No |
| `systemctl enable ssh` | Marks it to start at boot | ✅ Yes, but does **not** start it now |
| `systemctl enable --now ssh` | Does both in one step | ✅ Yes |

Other useful service commands:

```bash
sudo systemctl restart ssh    # apply config changes
sudo systemctl stop ssh       # shut it down
sudo systemctl reload ssh     # re-read config without dropping connections
```

## 6. Allow SSH through the firewall

If the server has UFW enabled, port 22 is blocked by default — the service runs, but nobody can reach it.

```bash
# Allow SSH (this is shorthand for "allow 22/tcp")
sudo ufw allow ssh

# Confirm the rule is there
sudo ufw status

# If the firewall itself is off, turn it on
sudo ufw enable
```

Prefer an explicit port if you changed it:

```bash
sudo ufw allow 2222/tcp
```

**firewalld (Fedora/RHEL):**

```bash
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

> **Symptom to remember:** `Connection timed out` usually means a firewall is **dropping** packets. `Connection refused` means the firewall let it through but **nothing is listening**.

## 7. Connect to the server

```bash
# Basic login
ssh username@192.168.1.50

# Login with a hostname
ssh anuj@server.example.com

# A non-default port
ssh -p 2222 anuj@192.168.1.50

# Run a single command and return
ssh anuj@192.168.1.50 "uptime"

# Copy a file over SSH
scp backup.tar.gz anuj@192.168.1.50:/home/anuj/

# Leave the session
exit          # or press Ctrl+D
```

### The first-connection prompt

```text
The authenticity of host '192.168.1.50' can't be established.
ED25519 key fingerprint is SHA256:9xJ2k... .
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

This is SSH asking: *"I have never met this server — is this really it?"*

- Type **yes** if you trust the machine (for example, it is your own VM on your LAN).
- Say **no** if you expected a different fingerprint — that can mean someone is impersonating the server (a man-in-the-middle).
- The fingerprint is saved in `~/.ssh/known_hosts`, so you are only asked once.
- If you rebuild the server, the old key stays in `known_hosts` and SSH refuses to connect with a big warning. Remove the stale line:

```bash
ssh-keygen -R 192.168.1.50
```

## 8. Keys instead of passwords (recommended)

A password can be guessed or brute-forced. A key cannot.

```bash
# 1. Create a key pair (ed25519 is the modern, small, fast choice)
ssh-keygen -t ed25519 -C "anuj@laptop"
#    ~/.ssh/id_ed25519      = PRIVATE key — never share, never copy to a server
#    ~/.ssh/id_ed25519.pub  = PUBLIC key  — safe to hand out

# 2. Copy the public key to the server
ssh-copy-id anuj@192.168.1.50

# 3. Log in — no password prompt
ssh anuj@192.168.1.50
```

The server stores your public key in `~/.ssh/authorized_keys`. During login the server sends a challenge that only your **private** key can answer, so the private key never leaves your machine.

Once keys work, disable password logins on the server in `/etc/ssh/sshd_config`:

```text
PasswordAuthentication no
```

```bash
sudo systemctl restart ssh
```

> **Lock yourself out risk:** before disabling passwords, confirm key login works **in a second terminal**, and keep an existing session open until you are sure.

## 9. Useful server settings (`/etc/ssh/sshd_config`)

| Setting | Meaning |
|---------|---------|
| `Port 22` | Port to listen on (change to reduce noise, not as real security) |
| `PermitRootLogin no` | Root cannot log in directly — log in as a user, then `sudo` |
| `PasswordAuthentication no` | Keys only |
| `AllowUsers anuj` | Only these users may log in |
| `MaxAuthTries 3` | Limit failed attempts per connection |

After editing:

```bash
sudo sshd -t                 # test the config — catches typos before a restart
sudo systemctl restart ssh
```

## 10. Troubleshooting

| Message | Likely cause | Fix |
|---------|--------------|-----|
| `Connection refused` | `sshd` not running, or wrong port | `sudo systemctl start ssh`, check `ss -tlnp \| grep :22` |
| `Connection timed out` | Firewall blocking, wrong IP, wrong network | `sudo ufw allow ssh`, `ping` the host |
| `Permission denied (publickey)` | Server wants a key you do not have | `ssh-copy-id`, check `~/.ssh/authorized_keys` and its permissions |
| `Permission denied (publickey,password)` | Wrong username or password | Check the user exists; try `ssh -v` |
| `Host key verification failed` | Server was rebuilt; old key in `known_hosts` | `ssh-keygen -R host` |
| `Too many authentication failures` | Agent offering too many keys | `ssh -o IdentitiesOnly=yes -i ~/.ssh/id_ed25519 user@host` |
| `WARNING: UNPROTECTED PRIVATE KEY FILE` | Key file is world-readable | `chmod 600 ~/.ssh/id_ed25519` |
| Works locally, not remotely | Listening only on `127.0.0.1` | Set `ListenAddress 0.0.0.0` or the LAN IP |

**Debug with one flag:**

```bash
ssh -v anuj@192.168.1.50     # -v, -vv, -vvv = increasing detail
```

| Task | Command |
|------|---------|
| Client version | `ssh -V` |
| Check client package | `dpkg -l \| grep openssh-client` |
| Check server package | `dpkg -l \| grep openssh-server` |
| Update package list | `sudo apt update` |
| Install server | `sudo apt install openssh-server` |
| Status | `sudo systemctl status ssh` |
| Start now | `sudo systemctl start ssh` |
| Start at boot | `sudo systemctl enable ssh` |
| Restart after config change | `sudo systemctl restart ssh` |
| Allow through firewall | `sudo ufw allow ssh` |
| Connect | `ssh user@host` |
| Connect on another port | `ssh -p 2222 user@host` |

| Copy a file | `scp file user@host:/path/` |

| Test server config | `sudo sshd -t` |
| Remove a stale host key | `ssh-keygen -R host` |
| Leave | `exit` |

## Summary

- **SSH = encrypted remote login**; client on your machine, `openssh-server` on the target, port 22.
- Check with `ssh -V` and `dpkg -l | grep openssh`; install with `sudo apt install openssh-server`.
- `systemctl start` runs it now, `enable` keeps it running after reboot, `enable --now` does both.
- Open the firewall with `sudo ufw allow ssh`, or the service is unreachable.
- Prefer **keys** over passwords, and never expose SSH to the internet with password login and root login enabled.
