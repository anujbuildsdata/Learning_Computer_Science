# Reserved IP Address Ranges (CIDR Notation)

> **Simple meaning:** some blocks of IPv4 addresses are **never given to a normal device on the internet**. They are kept for special jobs — private networks, testing, broadcasting, multicast, documentation. This note lists them and explains what each one is for.

---

## 1. What a reserved range is

Think of the IPv4 space as a **giant apartment building with 4.3 billion units**. Most units are rented out to real devices. A few floors are reserved:

- some for **internal use** (private networks),
- some for the **building's own machinery** (loopback, "this network"),
- some for **practice flats that are never rented** (documentation/test ranges),
- some for **announcements to everyone at once** (multicast, broadcast).

Routers on the public internet are configured to **drop** traffic to most of these ranges, so an address like `10.0.0.5` can exist on millions of networks without ever clashing.

---

## 2. How to read `/n` (CIDR notation)

`192.168.0.0/16` means: **the first 16 bits are fixed, the rest are free.**

| Part | Meaning |
|------|---------|
| `192.168.0.0` | The starting address of the block |
| `/16` | How many leading bits are the **network** part |
| Remaining bits | 32 − 16 = 16 bits for **hosts** → 2¹⁶ = 65,536 addresses |

```text
/8   → 2^24 = 16,777,216 addresses      (one whole first octet fixed)
/10  → 2^22 =  4,194,304 addresses
/12  → 2^20 =  1,048,576 addresses
/15  → 2^17 =    131,072 addresses
/16  → 2^16 =     65,536 addresses
/24  → 2^8  =        256 addresses
/32  → 2^0  =          1 address
```

**The rule:** every step you add to the slash number **halves** the block; every step you remove **doubles** it. That is all `/n` means.

## 4. The ranges, one by one, in plain words

### `0.0.0.0/8` — "this network"
Not a real destination. `0.0.0.0` as a source means *"I don't have an address yet"* (used during DHCP). As a destination in a server config, it means *"listen on every interface"* — that is what `0.0.0.0:8080` means in `ss` output.

### `10.0.0.0/8` — private, the big one
The largest private block: 16.7 million addresses. Used by enterprises, cloud VPCs (AWS picks `10.0.0.0/16` style blocks by default), VPNs who want to avoid clashing with a home `192.168.x.x` network, and Docker/Kubernetes internal networks.

### `100.64.0.0/10` — carrier-grade NAT
When your ISP does not have enough public IPv4 addresses, it puts you behind **another** layer of NAT. The address you get may be `100.64.x.x`. Consequence: **you cannot accept incoming connections**, which breaks port forwarding, hosting a game server, and some VPN setups. Related sign: your router's "WAN IP" is in this range.

### `127.0.0.0/8` — loopback
"Me, myself." Anything sent here never leaves the machine.
- `127.0.0.1` = `localhost` (the usual one)
- The whole `/8` is loopback, not just that single address
- Handy for running a local server: `python3 -m http.server` listening on `127.0.0.1:8000`

### `169.254.0.0/16` — link-local (APIPA)
A device gives itself one of these **when DHCP fails**. It can talk to other devices on the same cable/Wi-Fi that also failed, and nothing else.
> Seeing `169.254.x.x` is a classic symptom of a **broken DHCP server, bad cable, or wrong Wi-Fi password**.

### `172.16.0.0/12` — private, medium
Covers `172.16.0.0` – `172.31.255.255` — note it is **not** all of `172.x`. `172.17.0.1` is Docker's default bridge gateway. `172.32.x.x` and above are public.

### `192.0.0.0/24` — IETF protocol assignments
Small block reserved for special technical uses (protocol anycast addresses). You will rarely touch it.

### `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` — TEST-NET 1, 2, 3
**Fake addresses for examples.** They are guaranteed never to belong to a real server, so documentation, tutorials and textbooks use them freely. If you see `203.0.113.5` in a manual, it is a placeholder. (IPv6 equivalent: `2001:db8::/32`.)

### `192.88.99.0/24` — 6to4 relay (deprecated)
Was used to reach IPv6 over IPv4. The mechanism is deprecated; the block stays reserved so old configs do not suddenly point at a real machine.

### `192.168.0.0/16` — private, the home one
What almost every home router hands out: `192.168.0.x` or `192.168.1.x`. Covers `192.168.0.0` – `192.168.255.255`.

### `198.18.0.0/15` — benchmarking
Reserved for measuring network performance. Some VPN/proxy tools also use it to capture traffic locally. Covers `198.18.x.x` and `198.19.x.x`.

### `224.0.0.0/4` — multicast
One sender, many receivers. Used by streaming, IPTV, routing protocols (OSPF uses `224.0.0.5`), and mDNS/Bonjour (`224.0.0.251` for `.local` names). Multicast addresses are **destinations only** — never assign one to a host.

### `240.0.0.0/4` — reserved for the future
`240.0.0.0` – `255.255.255.254`. Not assigned; kept for future needs. Class E in the old class system.

### `255.255.255.255` — limited broadcast
"Everyone on this local network." Stays inside the LAN; routers do not forward it. DHCP discovery uses it as the destination because the client does not yet know any address.

## 5. The ones worth memorising

| Address | Meaning in one line |
|---------|---------------------|
| `127.0.0.1` | This machine (localhost) |
| `0.0.0.0` | "All interfaces" when listening, "no address yet" as a source |
| `255.255.255.255` | Everyone on this LAN |
| `10.x.x.x` / `172.16–31.x.x` / `192.168.x.x` | Private, never on the internet |
| `169.254.x.x` | DHCP failed — self-assigned link-local |
| `224.x.x.x` | Multicast group |

## 6. Why you should care in practice

- **Firewall rules** must know that "allow from `192.168.0.0/16`" only makes sense on a LAN.
- **VPN design** often requires picking a private block that does not clash with the office (`10.8.0.0/24` is popular because home routers almost never use `10.x`).
- **Security**: a server that responds on `0.0.0.0` is reachable from every interface, including the public one. Binding to `127.0.0.1` keeps it local.
- **Debugging**: `169.254.x.x` on your laptop means the DHCP problem, not the website.
- **Documentation**: using a real `8.8.8.8`-style address in an example is bad practice; TEST-NET ranges exist for that reason.

---

## 7. Summary

- `/n` fixes the first *n* bits; the rest are host bits, giving `2^(32-n)` addresses.
- **RFC 1918 private blocks** are `10/8`, `172.16/12`, `192.168/16` — reusable anywhere, never routed publicly.
- **Loopback** is `127/8`; **link-local** is `169.254/16`; **multicast** is `224/4`; **broadcast** is `255.255.255.255`.
- **TEST-NET 1/2/3** are for documentation only.
- Anything not in this table is a normal public address.
