# Part 1 — Core Concepts

## 1. Tunneling

**Simple meaning:** Tunneling means **wrapping one type of data inside another type of data** so it can travel safely across a network.

### Real-life analogy

Imagine you want to send a **letter (private data)**. You put it inside a **sealed envelope**, and the envelope travels through the normal postal system. Nobody on the way can read the letter — they only see the envelope.

That "envelope" is the **tunnel**, and the letter is your **real data**.

```
Your data  →  [ wrapped in a tunnel header ]  →  Internet  →  [ unwrapped ]  →  Destination
```

### Why is it used?

| Reason | Explanation |
|--------|-------------|
| **Security** | Data is encrypted, so no one can read it in transit. |
| **Privacy** | Hides what kind of traffic you are sending. |
| **Compatibility** | Lets a protocol travel over a network that normally doesn't support it. |

### Common types

- **VPN tunnel** – the whole internet connection is wrapped and encrypted.
- **SSH tunnel** – forwards a port securely through an SSH connection.
- **IP-in-IP tunnel** – an IP packet packed inside another IP packet.

> Think of tunneling as **a private car inside a public train**. The train carries everyone, but your car stays private and locked.

## 2. VPN (Virtual Private Network)

**Simple meaning:** A VPN creates a **private, encrypted connection over the public internet**. It is "virtual" because no new physical wire is installed — the internet itself is used as the road.

### Real-life analogy

Normally, you drive on a **public road** where anyone can see where you go. A VPN is like a **private, tinted tunnel** built over that same road: people know a car passed, but not who you are or where you went.

### How it works (step by step)

1. Your device connects to a **VPN server**.
2. All your data is **encrypted**.
3. The encrypted data travels through an **encrypted tunnel**.
4. The VPN server decrypts it and sends it to the destination.
5. The website sees the **VPN server's IP**, not yours.

```
[ You ] ──encrypted tunnel──> [ VPN Server ] ──> [ Website ]
                                        (sees VPN's IP, not yours)
```

### What a VPN gives you

- **Privacy** – hides your IP address.
- **Security** – protects data on public Wi-Fi.
- **Access** – lets you appear in another country.

### VPN vs Proxy

| Feature | VPN | Proxy |
|---------|-----|-------|
| Encrypts traffic | Yes | Usually no |
| Hides IP | Yes | Yes |
| Protects whole device | Yes | Only one app/browser |
| Speed | Usually slower (encryption) | Faster |

> **Important:** A VPN hides your traffic from others, but the **VPN provider itself can see it**. Always trust the provider.

## 3. ISP / NSP

**ISP = Internet Service Provider**
**NSP = Network Service Provider**

**Simple meaning:** These are the **companies that sell you the internet**.

### Real-life analogy

An ISP is like a **water supply company**. You don't build pipes to every website in the world yourself — you pay a company that already has the pipes, and it delivers water (internet) to your home.

### Difference between ISP and NSP

| Term | Who it serves | Example |
|------|---------------|---------|
| **ISP** | End users (homes, shops, offices) | Jio, Airtel, BSNL, Comcast |
| **NSP** | Other providers / large networks | Backbone carriers that connect ISPs |

> The internet is **providers connected to providers**, all the way up to huge undersea cables.

## 4. PDU (Protocol Data Unit)

**Simple meaning:** A PDU is simply **the name of the data chunk at each layer** of networking. The data stays the same — only its name and wrapper change.

### Real-life analogy

Think of sending a parcel:

| Step | Real life | Networking name |
|------|-----------|-----------------|
| Write the message | Letter | **Data** |
| Put it in an envelope with a port number | Envelope | **Segment** |
| Add the address | Parcel box | **Packet** |
| Load it on the delivery truck | Truck | **Frame** |
| Send it as electrical signals | Road | **Bits** |

### PDU by layer (OSI model)

| OSI Layer | PDU Name | Example |
|-----------|----------|---------|
| Application | **Data** | HTTP message |
| Transport | **Segment** (TCP) / **Datagram** (UDP) | Port numbers added |
| Network | **Packet** | IP address added |
| Data Link | **Frame** | MAC address added |
| Physical | **Bits** | 1s and 0s on the wire |

> **Memory trick:** **D**ata → **S**egment → **P**acket → **F**rame → **B**its = **"Do Some People Forget Bits?"**

Each layer **adds its own header** — this process is called **encapsulation**. The receiver removes the headers one by one (**decapsulation**).

## 5. Dark Web

**Simple meaning:** The dark web is a **small part of the internet that normal browsers and search engines cannot reach**. It requires special software (like **Tor**) to access.

### The three "layers" of the web

| Layer | What it is | Example |
|-------|------------|---------|
| **Surface Web** | Indexed by Google, open to everyone | Wikipedia, YouTube |
| **Deep Web** | Not indexed, needs login or permission | Email inbox, bank account |
| **Dark Web** | Deliberately hidden, needs special tools | Tor `.onion` sites |

> **Deep web ≠ dark web.** Your Gmail inbox is deep web. The dark web is intentionally hidden.

### How Tor hides you

Tor sends your traffic through **three random relays** (computers run by volunteers):

```
You → Relay 1 → Relay 2 → Relay 3 → Destination
```

- Relay 1 knows **you**, but not the destination.
- Relay 3 knows the **destination**, but not you.
- No single relay knows both.

This is called **onion routing** — like layers of an onion, each peeled at a different place.

> **Note:** The dark web is not automatically illegal. It is used by journalists, activists, and privacy-focused people — but also by criminals. Access it responsibly.

## 6. ICMP (Internet Control Message Protocol)

**Simple meaning:** ICMP is the **"messenger and doctor" of the internet**. It does not carry your data — it carries **error reports and diagnostic messages**.

### Real-life analogy

Imagine a delivery service. The truck carries parcels (your data). But sometimes a **messenger on a bike** comes back and says:

- "The address doesn't exist."
- "The road is blocked."
- "Slow down, too much traffic."

That messenger is **ICMP**.

### What ICMP is used for

| Use | Explanation |
|-----|-------------|
| **Error reporting** | "Destination unreachable", "Time exceeded" |
| **Diagnostics** | `ping` and `traceroute` use it |
| **Network health** | Checking if a host is alive |

### Common ICMP messages

| Type | Meaning |
|------|---------|
| **Type 0** | Echo Reply (ping response) |
| **Type 3** | Destination Unreachable |
| **Type 8** | Echo Request (ping request) |
| **Type 11** | Time Exceeded (TTL expired — used by traceroute) |

> ICMP works at the **Network layer (Layer 3)**. It has **no ports** — it is not TCP or UDP.

## 7. Networking Terms

### Bandwidth

**Simple meaning:** The **maximum amount of data** a connection can carry in a given time.

**Analogy:** The **width of a pipe**. A wider pipe can carry more water at once.

- Measured in **Mbps / Gbps** (megabits or gigabits per second).
- It is the **theoretical limit**, not what you always get.

### Throughput

**Simple meaning:** The **actual amount of data** that successfully moves in a given time.

**Analogy:** The water that **actually comes out** of the tap — some is lost to leaks, pressure, or traffic.

```
Bandwidth = size of the pipe
Throughput = water actually delivered
```

> **Throughput is always ≤ Bandwidth.** The gap is caused by latency, congestion, and packet loss.

### Latency

**Simple meaning:** The **time delay** for data to travel from source to destination.

**Analogy:** How long a letter takes to reach your friend, regardless of how big the envelope is.

- Measured in **milliseconds (ms)**.
- Low latency = fast response (good for gaming, video calls).
- High latency = lag, delay.

### Bandwidth vs Throughput vs Latency

| Term | Question it answers | Unit |
|------|---------------------|------|
| Bandwidth | How **much** can travel? | Mbps |
| Throughput | How much **actually** travels? | Mbps |
| Latency | How **long** does it take? | ms |

### WLAN (Wireless Local Area Network)

**Simple meaning:** A **local network without wires** — Wi-Fi is the most common example.

- **LAN** = Local Area Network (one building, one home).
- **WLAN** = the wireless version of LAN.

**Analogy:** Instead of cables connecting rooms, invisible radio waves connect devices.

| Feature | LAN | WLAN |
|---------|-----|------|
| Connection | Cables (Ethernet) | Radio waves (Wi-Fi) |
| Speed | Faster, stable | Convenient, can drop |
| Mobility | Limited | Move freely |

# Part 2 — Commands

## Ping

**What it does:** Tests **whether a device is reachable** by sending ICMP **Echo Requests** and waiting for **Echo Replies**.

**Analogy:** Shouting "Are you there?" and waiting for "Yes, I'm here!"

```bash
# Basic ping (Linux / macOS / Windows)
ping google.com

# Send only 4 pings (Linux / macOS)
ping -c 4 google.com

# Send only 4 pings (Windows)
ping -n 4 google.com

# Ping an IP address
ping 8.8.8.8
```

**How to read the output:**

```text
64 bytes from 142.250.183.14: icmp_seq=1 ttl=117 time=12.4 ms
```

| Field | Meaning |
|-------|---------|
| `bytes` | Size of the reply |
| `icmp_seq` | Sequence number (order of packets) |
| `ttl` | Time To Live — how many hops are left |
| `time` | Round-trip latency in ms |

> **No reply?** The host may be offline, blocking ICMP, or a firewall is in the way.

---

## Traceroute

**What it does:** Shows **every router (hop)** a packet passes through to reach the destination.

**Analogy:** Tracking a parcel and seeing **every city** it stops in before reaching you.

```bash
# Linux / macOS
traceroute google.com

# Windows (different spelling!)
tracert google.com

# Limit hops (Linux)
traceroute -m 10 google.com

# Use ICMP instead of UDP (Linux)
traceroute -I google.com
```

**Sample output:**

```text
1  _gateway (192.168.1.1)        1.2 ms
2  10.10.0.1                     5.4 ms
3  * * *                          (no reply)
4  142.250.183.14               12.8 ms
```

| Symbol | Meaning |
|--------|---------|
| Each line | One **hop** (router) |
| `* * *` | Router didn't reply (blocked or busy) |
| Time values | Latency to that hop |

**How it works (clever trick):** It sends packets with a **TTL of 1, then 2, then 3…** Each router that expires the TTL sends back an ICMP **"Time Exceeded"** message — revealing its address.

## Curl

**What it does:** Transfers data to/from a server. Most commonly used to **test APIs** and **download/inspect web content**.

**Analogy:** A **universal delivery boy** who can pick up or drop off data using many different methods (HTTP, FTP, etc.).

```bash
# Fetch a web page
curl https://example.com

# Download a file, keeping the original name
curl -O https://example.com/file.zip

# Save output to a specific filename
curl -o myfile.zip https://example.com/file.zip

# Follow redirects
curl -L https://example.com

# Show response headers only
curl -I https://example.com

# Send a GET request to an API
curl https://api.github.com/users/octocat

# Send a POST request with JSON data
curl -X POST https://api.example.com/data \
     -H "Content-Type: application/json" \
     -d '{"name":"Anuj"}'
```

**Common flags:**

| Flag | Meaning |
|------|---------|
| `-O` | Save with the remote filename |
| `-o FILE` | Save to a chosen filename |
| `-L` | Follow redirects |
| `-I` | Fetch headers only |
| `-X METHOD` | Set HTTP method (GET, POST, PUT, DELETE) |
| `-H` | Add a header |
| `-d` | Send data in the request body |

> **Curl vs browser:** A browser shows a page nicely; curl shows the **raw data**. That's why developers love it for debugging APIs.

---

## Wget

**What it does:** **Downloads files** from the web. Great for large files and recursive downloads.

**Analogy:** A **download specialist** — it grabs files and keeps going, even if the connection drops.

```bash
# Download a file
wget https://example.com/file.zip

# Save with a different name
wget -O myfile.zip https://example.com/file.zip

# Resume an interrupted download
wget -c https://example.com/bigfile.iso

# Download in the background
wget -b https://example.com/file.zip

# Download a whole website (careful!)
wget -r https://example.com
```

**Common flags:**

| Flag | Meaning |
|------|---------|
| `-O FILE` | Save to a chosen filename |
| `-c` | Continue/resume a partial download |
| `-b` | Run in the background |
| `-r` | Recursive download (whole site) |
| `-q` | Quiet mode |

### Curl vs Wget

| Feature | Curl | Wget |
|---------|------|------|
| Best for | APIs, testing, many protocols | Downloading files |
| Resume downloads | Yes (`-C -`) | Yes (`-c`) |
| Recursive download | No | Yes (`-r`) |
| API debugging | Excellent | Basic |
| Available on Windows | Yes (built-in) | Usually separate install |

## Quick Summary

- **Tunneling** protects data by wrapping it.
- **VPN** = a tunnel for your whole internet connection.
- **ISP/NSP** = the companies that carry your internet.
- **PDU** = the data's name at each layer (Data → Segment → Packet → Frame → Bits).
- **Dark Web** = hidden internet, needs Tor.
- **ICMP** = the internet's messenger for errors and diagnostics.
- **Bandwidth** is the limit, **throughput** is reality, **latency** is delay.
- **WLAN** is wireless LAN (Wi-Fi).
- **ping** checks reachability, **traceroute** shows the path, **curl** tests APIs, **wget** downloads files.
