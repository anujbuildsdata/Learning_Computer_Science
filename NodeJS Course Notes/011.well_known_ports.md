# Well-Known Ports — The Numbers You Should Recognise

> **Simple meaning:** a **well-known port** is a fixed number (0–1023) that the whole world agrees means one particular service. If something answers on port 80, everyone assumes it is a web server. No configuration is needed — the number *is* the agreement.

For the concept of ports and the three ranges, see [010](010.ranges_of_ports.md).

---

## 1. Who decides these numbers

- **IANA** keeps the official registry: *Service Name and Transport Protocol Port Number Registry*.
- On Linux and macOS, the same list also exists offline in **`/etc/services`**:

```bash
grep -E '^(http|https|ssh|domain)\s' /etc/services
# ssh             22/tcp
# domain          53/tcp
# domain          53/udp
# http            80/tcp
# https          443/tcp
```

- "Well-known" strictly means **0–1023** and requires root privileges to bind. Many numbers above 1023 are also de-facto standard (3306, 5432, 3389) and are included below because you will meet them just as often.

## 2. The main table

| **Port** | **Protocol / Service** | **Description** |
|----------|------------------------|-----------------|
| **20, 21** | FTP (File Transfer Protocol) | 21 = control channel (commands, login); 20 = data channel in active mode. Unencrypted. |
| **22** | SSH (Secure Shell) | Encrypted remote login, file copy (scp/sftp) and tunnelling. |
| **23** | Telnet | Remote login in **plain text**. Obsolete and unsafe — replaced by SSH. |
| **25** | SMTP | Server-to-server email delivery. |
| **53** | DNS | Resolves names to IP addresses. Mostly UDP; TCP for large answers and zone transfers. |
| **67, 68** | DHCP | 67 = server (listens), 68 = client. Broadcast on UDP. |
| **69** | TFTP | Tiny, unencrypted UDP file transfer (used for firmware and PXE boot). |
| **80** | HTTP | Plain web traffic. |
| **110** | POP3 | Downloads email from a mailbox (usually then deletes it). |
| **123** | NTP | Clock synchronisation over UDP. |
| **143** | IMAP | Reads email on the server, keeps it there, syncs across devices. |
| **161, 162** | SNMP | 161 = monitoring queries; 162 = traps (alerts sent by the device). |
| **389** | LDAP | Directory lookups (users, groups) — e.g. Active Directory. |
| **443** | HTTPS | Web traffic inside TLS encryption. |
| **445** | SMB | Windows file and printer sharing. Frequently attacked — never expose to the internet. |
| **465** | SMTPS | SMTP wrapped in TLS (implicit TLS). |
| **514** | Syslog | Log messages over UDP. |
| **587** | SMTP submission | How your mail client **sends** mail, with authentication + STARTTLS. |
| **636** | LDAPS | LDAP over TLS. |
| **993** | IMAPS | IMAP over TLS. |
| **995** | POP3S | POP3 over TLS. |
| **1433** | Microsoft SQL Server | Database connections. |
| **1521** | Oracle Database | Listener port. |
| **3306** | MySQL / MariaDB | Database connections. |
| **3389** | RDP | Windows Remote Desktop. |
| **5432** | PostgreSQL | Database connections. |
| **5900** | VNC | Remote screen sharing (usually unencrypted — tunnel it). |
| **6379** | Redis | In-memory data store. No auth by default — keep it local. |
| **8080** | HTTP (alternative) | Proxies, development servers, app servers (Tomcat). |
| **8443** | HTTPS (alternative) | The HTTPS twin of 8080. |
| **27017** | MongoDB | Database. Historically open by default — a classic breach. |

## 3. Grouping them makes them easy to remember

### Web
`80` HTTP · `443` HTTPS · `8080` / `8443` alternates (dev servers, proxies)

**Trick:** 80 and 443 are the only two you need for ordinary browsing. If a link ends in `:8080`, it is usually a development machine.

### Email
There are two separate jobs, and mixing them up is the usual confusion:

| Job | Plain | Encrypted | Notes |
|-----|-------|-----------|-------|
| Send mail (client → server) | 25 (server-to-server only) | **587** (STARTTLS) or 465 (implicit TLS) | Use 587 in mail clients |
| Fetch mail (POP3) | 110 | 995 | Downloads and usually removes |
| Read mail on server (IMAP) | 143 | 993 | Keeps mail on the server; better for multiple devices |

### Remote access
`22` SSH · `23` Telnet (dead, insecure) · `3389` RDP · `5900` VNC

**Rule:** SSH and RDP should never be open to the whole internet without protection (VPN, key-only auth, or a bastion host).

### Name and configuration services
`53` DNS · `67/68` DHCP · `123` NTP · `161/162` SNMP · `389/636` LDAP

These keep the network running. DNS and DHCP are the two you will debug most.

### Files
`20/21` FTP · `69` TFTP · `445` SMB · `22` (scp/sftp ride on SSH)

**Note:** plain FTP sends passwords in clear text. Prefer SFTP (which is just SSH on port 22) or FTPS.

### Databases
`3306` MySQL · `5432` PostgreSQL · `1433` MSSQL · `1521` Oracle · `27017` MongoDB · `6379` Redis

**Rule:** a database should listen on `127.0.0.1` or a private network, never on the public internet.

## 4. Checking ports on a real machine

```bash
# What is listening right now? (u = UDP, t = TCP, l = listening, p = process, n = numeric)
sudo ss -tulpn

# Just the well-known ones
sudo ss -tulpn | awk '$5 ~ /:(80|443|22)$/'

# Is a remote port open? (nc = netcat)
nc -zv example.com 443          # "succeeded" or "Connection refused"
nc -zv -w 3 203.0.113.7 22      # 3 second timeout

# Test a web port properly
curl -I https://example.com

# Old-school check (telnet client often not installed)
telnet example.com 25
```

### Allowing a port through a firewall (UFW)

```bash
sudo ufw allow 22/tcp           # SSH
sudo ufw allow 443/tcp
sudo ufw allow 80/tcp
sudo ufw status numbered
```

### Changing a port

```bash
# sshd example: change from 22 to 2222 in /etc/ssh/sshd_config
sudo sed -i 's/^#\?Port .*/Port 2222/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```

> **Security reality check:** moving SSH from 22 to 2222 only stops lazy automated scans. It is **not** a substitute for key-based authentication, a firewall, or a VPN.

## 5. Common confusions

| Confusion | Clarification |
|-----------|---------------|
| 80 vs 8080 | Same protocol (HTTP), different number. 8080 needs no root and avoids clashing with an existing web server. |
| 443 vs 8443 | Same as above for HTTPS. |
| 25 vs 587 | 25 is for servers talking to servers; **587 is for mail clients sending mail**. |
| 143 vs 993 | Same service (IMAP); 993 is IMAP inside TLS from the first byte. |
| 110 vs 995 | Same service (POP3); 995 is the encrypted version. |
| 3306 vs 5432 | MySQL vs PostgreSQL — different products, not different versions. |
| "Port 443 is secure" | The port does not encrypt anything. **TLS** does. Anything can run on 443. |

## 7. Summary

- A well-known port is a **globally agreed number** for a service (0–1023, root required).
- The registry lives with **IANA** and locally in **`/etc/services`**.
- Web = 80/443, mail = 25/587/110/143/465/993/995, remote = 22/3389, databases = 3306/5432/1433.
- Use `ss -tulpn` to see what is actually listening, `nc -zv` to test reachability.
- Exposing 445, 3389, 5900 or a database port to the internet is one of the most common ways machines get compromised.
